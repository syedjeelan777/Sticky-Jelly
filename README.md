# 🍮 Sticky Jelly

A **web-first, grid-based logic puzzle** inspired by *Jelly Is Sticky*. Manipulate
sticky, deformable jelly blocks to reach goals across **300+ solver-verified
levels**, with undo, overworld progression, a relaxing procedural soundtrack and
a fully integrated **in-browser level editor**.

It is a zero-dependency static web app: plain HTML5 Canvas + vanilla JS, no build
step, no backend required.

---

## ▶️ Play

```bash
python3 -m http.server 8000 --bind 0.0.0.0
# open http://localhost:8000
```

or `npm start`. The whole game lives in static files, so it also deploys
directly to GitHub Pages / Netlify / any CDN.

### Controls
- **Arrow keys / WASD** or **on-screen D-pad** — push the selected jelly.
- **Click / tap** a jelly to select it (sticky clusters select as one).
- **Drag** a jelly to push it.
- **Z** undo · **R** reset · **H** hint.

## 🧠 The jelly physics

Each colour behaves differently — the heart of the puzzle design:

| Type | Colour | Behaviour |
|------|--------|-----------|
| **Sticky** | 🟣 | Sticks to walls & other sticky jellies — adjacent ones *gloop* into a cluster that moves as one. Falls only when un-anchored, so it can climb walls. |
| **Rigid** | 🟡 | A solid block that **never falls**. Fireproof & heavy (holds pressure plates). |
| **Squishy** | 🔵 | Deformable — obeys gravity and always drips down to the lowest cell. |
| **Bouncy** | 🔴 | Elastic — one push launches it **sliding** across empty cells until it hits something. |
| **Stone** | ⬛ | A pushable solid (Sokoban crate). Fireproof & heavy. |

**Hazards & elements:** 🔥 fire destroys non-fireproof jellies · ⭕ pressure
plates + gates open when a heavy block (stone/rigid) rests on a plate ·
⭐ goals must all be occupied by jellies.

There is **no timing, dexterity or randomness** — purely logical, with unlimited
step-by-step undo. Shape glyphs are drawn on every jelly so the game stays
playable in **colorblind mode** (toggle 👁️).

## 🗺️ Content

- **6 worlds × 50 levels = 300 levels**, generated by `tools/generate_levels.js`
  and **verified solvable** by a BFS solver (`js/solver.js`).
- A handful of hand-crafted tutorial seeds (first levels of Strawberry, Lemon
  and Cherry worlds).
- Mario-64-style progression: levels within a world can be solved in any order;
  a world unlocks after ~60% of the previous world, and the secret **Fruit Salad**
  world requires 100%.
- Progress is saved to `localStorage`.

## 🧪 Level editor

Open **“Open Level Editor”** from the overworld:

- Palette painting (tiles, jellies, stone, fire, plates, gates), click or drag.
- Undo/redo, resize, clear.
- **✓ Validate** — runs the solver to confirm the level is solvable.
- **▶ Test Play** — drops straight into the game on your level.
- **Export / Share** — JSON copy, file download, or a shareable URL (base64 in
  the fragment, e.g. `index.html#level=…`).
- **💾 Save to Custom** — your levels appear on the overworld.

## 🏗️ Architecture

Pure, framework-free JS with a strict separation:

| File | Role |
|------|------|
| `js/engine.js` | The entire puzzle rule set (pure logic, no DOM). Shared by game, solver, editor **and** the Node generator. |
| `js/solver.js` | BFS solver used for level validation, the editor's Validate button, and in-game hints. |
| `js/levels.js` | Auto-generated 300-level content (don't edit by hand). |
| `js/renderer.js` | Canvas renderer: animated jellies, fire, gates, goals, selection, colorblind glyphs. |
| `js/game.js` | Game screen: input, move/tween animation, undo history, win/fail, hints. |
| `js/editor.js` | Level editor. |
| `js/audio.js` | Procedural WebAudio SFX + ambient music (zero audio assets). |
| `js/main.js` | App shell: routing, overworld, progress persistence, unlock logic. |
| `tools/generate_levels.js` | Offline level generator (deterministic, `--seed`). |
| `tools/smoke_test.js` | Logic + DOM smoke tests. |

The engine/solver are written in a dual CommonJS/browser-global style, so the
same code runs in Node (generation, testing) and the browser (gameplay).

## 🛠️ Development

```bash
npm test            # logic + DOM smoke tests (jsdom for the DOM layer)
node tools/generate_levels.js --seed 1337   # regenerate js/levels.js
```

Regenerating levels runs the solver on every candidate and only ships solvable
ones — so `js/levels.js` is always safe to rebuild.
